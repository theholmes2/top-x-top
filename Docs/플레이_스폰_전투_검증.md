## 스폰 정책 변경 — 2026-11-16

현재 정책은 정기 시간 스폰을 유지하며, 타격으로 사망 처리가 성공한 직후 활성 적이 0마리인 경우에만 같은 Tick 한 마리를 즉시 보충한다. 2마리 중 한 마리를 처치하면 1마리가 남는다. 사망 연출 중인 dying 개체는 활성 수에 포함하지 않는다.

정기 스폰은 타격보다 먼저 처리된다. 같은 Tick 정기 스폰으로 활성 적이 남았다면 처치에 따른 보충은 없다. 전멸 보충은 정기 예정 시각을 변경하지 않는다. 이후 본문의 2026-11-05 관찰값은 당시 구현 기록이다.

Unity 6000.3.19f1 최신 컴파일 실패 false, 기존 Edit Mode 회귀 110개 및 새 Play Mode 전멸 보충 검사 14개를 통과했다. 2→1 보충 없음, 마지막 적 처치 보충 1회, dying 잔존, 정기 스폰·처치 동시 Tick, 예정 시각 보존, 400ms 후딜과 상한을 확인했다.

재현 검사는 Validation/2026-11-16-elimination-spawn-checks.cs.txt를 Play Mode에서 CLI eval로 실행한다. 기존 상한·종류 순환·풀 회귀 검사는 Validation/2026-11-05-flow-checks.cs.txt를 Edit Mode에서 실행한다.

## 현재 실행 흐름

1. CombatCompositionRoot가 PlayerState와 캐릭터당 SkillUseBrick 하나를 만들고, EnemyPoolGlue·EnemySpawnGlue·SpawnScheduleBrick을 타입으로 등록한다. 현재 컨테이너 안에서 Singleton으로 공유하고 IDisposable은 컨테이너가 추적한다. 도시/타워 Scope는 아직 분리하지 않았다.
2. SimulationTickGlue는 IStartable·ITickable·IDisposable EntryPoint다. Start에서 난이도를 설정하고 즉시 첫 프레임 처리를 한다.
3. TickAt의 순서는 스폰 기회 → 종류 순환 대여·새 State 초기화·위치 지정·활성화 → 먼저 등장한 생존 대상 선택 → 기본공격 요청 → 사망이면 스폰 담당을 통해 즉시 반환이다.
4. SpawnScheduleBrick은 처음 즉시, 이후 실제 시도 시각+1000ms로 다음 기회를 잡는다. 포화나 지연분을 저장·재생하지 않는다. 한 기회에 최대 한 마리다.
5. SkillUseBrick 생성자는 더 이상 target을 받지 않는다. `TryUse(long nowMs, CharacterState target)`이 현재 대상을 받고 캐릭터의 NextUseAtMs는 그대로 유지한다. 시간과 공격 효과 Brick은 Unity·컨테이너를 모른다.
6. 사망 반환은 활성 List에서 제거하고 전체·종류별 점유를 줄인 뒤 표시 순서를 갱신한다. 같은 GameObject를 재대여해도 State는 새로 생성하고 목록 맨 뒤에 추가한다.

## 순환과 상한

슬라임2·늑대1은 슬→슬→늑을 반복한다. 종류 수만큼만 탐색하여 포화된 종류를 건너뛰고, 한 번 성공하면 종료한다. 큰 수량을 펼친 반복 목록은 만들지 않았다.

전체 상한이 찼을 때는 커서·남은 순환 수량을 소비하지 않는다. 그렇지 않으면 전체 상한1에서 매번 첫 종류로 차례가 초기화되어 늑대가 계속 밀릴 수 있어 보완했다. 모든 종류가 가득 차도 유한 탐색 후 정상 false다. 전체 상한10·종류별 합계3도 오류나 자동 보정 없이 실제 가능한 3개까지만 등장한다.

표시 순서는 활성 목록 크기-인덱스-1이며 short 범위 안으로 제한한다. 누적 생성 횟수를 사용하지 않는다. 현재 소수 몬스터(예시 최대5)에서 먼저 등장한 생존 적이 겹침의 앞에 보인다. 위치는 모두 우측 한 점이며 분산·거리는 계산하지 않는다.

기본 난이도 전체 상한은 기존 종류별 합계인 임시값 1/3/3/4/5다. 확정 밸런스가 아니다.

## 검증 결과

- 사망 시 한 번 반환·계수 감소, 재대여의 동일 GameObject/새 State/기본 체력, 등장 순서 타깃과 재대여 맨 뒤, 표시 순서2/1/0을 확인했다.
- 풀→스폰 및 스폰→풀의 두 종료 순서와 중복 Dispose를 별도로 확인했다.
- 실제 게임 첫 프레임을 일시정지 상태에서 확인: frame1, 게임 시각0ms, 적1, HP37, 첫 스폰0ms·첫 공격0ms. 시작 즉시 공격8이 적용된 결과다. 다음 사용 가능 시각은1000ms다.

## 한계·다음 범위

TrySpawn으로 얻은 개체는 같은 EnemySpawnGlue.TryDespawn으로 반환한다. 외부 Destroy나 직접 pool.TryReturn으로 스폰 계수를 우회하는 흐름은 지원하지 않는다. 현재 기본공격 사망은 반드시 중앙 Tick이 이 경로로 처리한다.

강제 프로세스 종료에서 Dispose를 보장하지 않는다. 이번 정리는 앱이 살아 있는 상태의 Scope 종료·씬 전환을 위한 것이다. 플레이 중 미사용 종류 풀 정리, 도시/타워 Scope 분리는 미결정이다.

Editor 검증이며 빌드·실기기 성능·모든 프레임률 조합은 미검증이다. 애니메이션·UI·보상·적 반격·물리·직업 보정·서버·저장·오프라인·타워는 추가하지 않았다. 이벤트/R3/DOTween/VM을 의미 없이 넣지 않았다. 서버·클라우드 변경이 없어 재배포가 필요하지 않다. 커밋·푸시·배포하지 않았다.
