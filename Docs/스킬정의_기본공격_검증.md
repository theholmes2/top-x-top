# 기본공격도 스킬 정의로 사용 — 2026-11-02

> 2026-11-03 후속: 기본공격1000ms와 실제 사용 검사/중앙 요청을 연결했다. [기본공격_1초쿨타임_검증.md](기본공격_1초쿨타임_검증.md)를 따른다. 아래200ms/정의만 준비 문구는 이전 단계 기록이다.

## 이번 요소의 결과

일반공격과 강타를 같은 SkillConfig SO 타입으로 정의하고, 같은 AttackBrick에 위력 숫자만 전달한다. 스킬 이름/ID에 따른 전용 공격 CS나 분기는 없다. SkillConfig는 고정 데이터이고 AttackBrick은 Unity를 참조하지 않는 순수 C#이다.

| 에셋 | SkillId | 표시명 | 기본 쿨타임 정의 | 위력 천분율 |
|---|---|---|---|---|
| Assets/Configs/Skill/BasicAttackConfig.asset | basic_attack | 기본공격 | 200ms | 1000 = 1배 |
| Assets/Configs/Skill/SmashConfig.asset | smash | 강타 | 1000ms | 2000 = 2배 |

이 값은 임시 시험 수치다. 정의 SO에 마지막 사용 시각·남은 쿨타임·사용자 레벨을 넣지 않았다. Inspector의 Min은 입력 보조이며 미래 서버 검증을 대신하지 않는다.

## 생성자와 호출

```csharp
// 이미 만들어진 현재 상태 참조를 공유합니다.
var attack = new AttackBrick(player);

// 호출 측에서 실제 SO의 순수 위력 값만 전달합니다.
bool basicUsed = attack.TryAttack(enemyA, basicConfig.PowerPermille, out int basicDamage);
bool smashUsed = attack.TryAttack(enemyB, smashConfig.PowerPermille, out int smashDamage);
```

생성자는 AttackBrick(CharacterState attacker) 그대로다. 메서드는 TryAttack(CharacterState target, int powerPermille, out int appliedDamage)로 변경했다. 같은 Brick이 현재 공격자 스탯을 읽고 매 요청의 다른 대상을 공격할 수 있다. 대상은 서로 독립적인 EnemyState 인스턴스다. 이 예시는 연결 방식이며 Scene 실행기나 Glue를 새로 구현한 것이 아니다.

## 피해 수치

1. 공격력과 위력은 0~int.MaxValue 정수다. 음수 위력은 ArgumentOutOfRangeException이며 HP를 변경하지 않는다.
2. scaledAttack = (long)현재공격력 × powerPermille / 1000. 양수 정수 나눗셈으로 소수점 이하는 버린다.
3. 방어력을 뺀 뒤 0~int.MaxValue 범위로 제한하고 HP에 한 번 적용한다.
4. appliedDamage는 적용 전 HP - 적용 후 HP다. 계산 피해가 HP보다 커도 실제 감소량만 반환한다.

int 최대값 두 개의 곱도 long 범위 안에 들어간다. 곱셈 전에 long으로 변환하고, 큰 계산 피해는 int로 변환하기 전에 제한한다. 0피해·0위력도 유효한 대상이면 성공 true다. null/자기 대상/사망 개체는 false와 appliedDamage=0이며 상태가 바뀌지 않는다. 생성자 null 공격자는 기존처럼 예외다.

## 검증

실행 중인 새 top x top Unity Editor 6000.3.19f1에서 실제 Config 에셋을 생성하고 해당 에셋 데이터를 읽어 21개 검사를 통과했다. 추가 영구 테스트 CS·Scene·게임 루프를 만들지 않고 CLI eval의 임시 검사로 수행했다.

- 실제 플레이어 공격력8/슬라임 방어0에서 기본공격8, 강타16. 둘 다 요청당1회.
- 대상 교체·개체 독립성·공격자 HP 불변, 현재 공격력·현재 방어력 변경 반영.
- 0피해/0위력 성공, HP5 초과 피해는 실제5 반환, 사망/자기/null 대상 및 사망 공격자 거절.
- 음수 위력 상태 미변경, 1.5배 소수점 버림 후 방어력 차감, 아주 작은 배율과 int 최대 배율/공격력의 오버플로 경계.
- 같은 SO를 여러 공격에서 읽어도 JSON 내용/dirty 상태 불변.
- 시간 없이 두 번 요청하면 두 번 적용됨: 쿨타임 실행 검사가 아직 없음을 확인.

Unity 최신 컴파일 상태는 최종 보고 때 별도로 확인했다. 기존 AttackBrick.cs.meta는 보존했고 새 폴더/스크립트/에셋 meta는 Unity가 생성했다. Git 기존 변경은 유지했고 이전 top of top은 수정하지 않았다.

## 구현하지 않은 것

쿨타임은 SO의 정의만 준비됐다. 마지막 사용 시각·남은 시간·사용 거절 검사·자동 일정·예약 큐·슬롯·마나·효과 상속 프레임워크·광역/회복/버프·View/VM/R3/이벤트/DOTween·VContainer/Root·중앙 Update 실행·Scene 전투·서버는 추가하지 않았다. 기본공격이 스킬 데이터가 되었다고 완성된 스킬 실행기나 게임이 생긴 것은 아니다.

향후 수동/자동/큐의 공통 사용 검사가 승인되면 대상·쿨타임·자원을 확인한 뒤 이 1회 효과를 호출할 수 있다. 현재 Brick은 시간과 연출을 모르며 애니메이션 완료를 기다리지 않는다. 다음 기능으로 진행하지 않는다. 커밋·Push·PR·배포 없음.
